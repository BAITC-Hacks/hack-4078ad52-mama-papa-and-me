# Публикация MVP: Netlify + Neon

База изменений — коммит `3700ece`, ветка `codex/netlify-latest`. Это общий демонстрационный сайт без регистрации игроков. Сохранённые сценарии видны всем посетителям; не вводите приватные данные. Ключ OpenAI находится только на сервере. Локальная SQLite продолжает работать при отсутствии DATABASE_URL.

## 1. Создать базу Neon

В Neon создайте проект на Free, выберите регион рядом с регионом функций Netlify. В SQL Editor выполните содержимое [миграции](../src/storage/migrations/001-postgres.sql). Повторный запуск безопасен для существующих строк. Это новая облачная база: локальные сценарии автоматически не копируются.

В Connect скопируйте PostgreSQL connection string в переменную DATABASE_URL в Netlify. Не отправляйте строку в чат и не сохраняйте её в Git. Альтернативный запуск миграции: `npm run db:migrate` после установки DATABASE_URL в локальное окружение или защищённый .env.

## 2. Создать сайт через CLI без подключения GitHub

Работа ведётся только в `BAITC-Hacks/hack-4078ad52-mama-papa-and-me`. Новый репозиторий, fork и установка GitHub App Netlify в организацию не нужны. CLI загружает собранное приложение из локальной рабочей копии. Код и история остаются в исходном репозитории. Сборка выполняется на вашем компьютере; после публикации он не нужен для работы сайта.

Откройте PowerShell в корне рабочей копии с `package.json` и `netlify.toml`. Для текущей подготовленной ветки это:

```powershell
cd "C:\Users\Елена\Documents\Codex\2026-09-23\new-chat-3\work\hackalem-public"
node --version
npm.cmd --version
```

Нужен Node.js 22.20+ и npm. Установите зависимости и авторизуйтесь:

```powershell
npx.cmd --yes npm@11.20.0 ci
npm.cmd run netlify:login
npm.cmd run netlify:create
npm.cmd run netlify:status
```

`netlify:login` открывает браузер для входа в ваш Netlify. `netlify:create` создаёт пустой сайт в выбранном личном пространстве и привязывает его к папке, не подключая GitHub. Выполняйте create только один раз. Если сайт уже существует, вместо create используйте `npx.cmd --yes netlify-cli link` и выберите его. Локальная привязка в `.netlify/` исключена из Git.

Команды npm используют Netlify CLI через npx; при первом запуске нужен интернет для загрузки. Настройки сборки берутся из netlify.toml: Node 22, npm 11.20.0, команда `npm run build`, каталог `.next`, функции `netlify/functions`. Next.js требует адаптер Netlify OpenNext и серверные функции. Не используйте Netlify Drop, static export или загрузку папки исходников через Проводник.

Сохраните адрес созданного сайта. До публикации выполните миграцию Neon и задайте переменные из следующего раздела.

## 3. Переменные окружения

Задайте через Netlify UI. Они должны быть доступны функциям во время выполнения; переменные из раздела build.environment в netlify.toml для этого недостаточны. Если доступны scopes, выберите Builds и Functions. Изменение переменных требует нового деплоя.

| Имя | Значение |
| --- | --- |
| DEPLOY_TARGET | `netlify` |
| DATABASE_URL | Строка подключения из Neon, секрет |
| APP_ORIGIN | Точный адрес `https://имя-сайта.netlify.app`, без `/` в конце |
| WORKER_SECRET | Случайный секрет не менее 32 символов |
| OPENAI_API_KEY | Ваш собственный ключ OpenAI, секрет |
| OPENAI_MODEL | `gpt-6-astra`, проектный default сохранён |
| AI_ENABLED | Сначала `false`, после проверки расчёта и БД — `true` |
| AI_MAX_ANALYSIS_MINUTES | `12` |
| AI_DAILY_ANALYSIS_LIMIT | Сначала `10`, затем нужное число; default кода `50` |

WORKER_SECRET можно сгенерировать локально: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Не публикуйте его. Не используйте префикс NEXT_PUBLIC_ для секретов. Используйте свой ключ OpenAI, чтобы запросы расходовались из вашего API-проекта, а не через неявную интеграцию платформы.

Квота — число допущенных анализов за сутки UTC для всего сайта, не денежный лимит. Каждый анализ может содержать два платных этапа и веб-поиск. Неудачная или одновременная повторная заявка может израсходовать одно место в квоте; автоматического возврата нет. В актуальном интерфейсе анализ вызывается по запросу пользователя; каждый запуск учитывается в квоте. Симуляция остаётся доступной при исчерпании квоты.

Не включайте production-секреты для непроверенных preview-веток. Эта версия нацелена на один основной адрес; preview не должен вызывать worker production-сайта.

## 4. Собрать и опубликовать

После настройки окружения и базы, из той же папки:

```powershell
npm.cmd run netlify:build
```

Продолжайте только при успешной сборке. В этой среде Next.js ранее остановился на `spawn EPERM` после компиляции: полный результат Netlify-сборки ещё не подтверждён. Запуск из обычного PowerShell пользователя проверит, сохраняется ли ограничение вне окружения агента. Не отключайте проверку типов ради публикации.

Для публикации на основной адрес:

```powershell
npm.cmd run netlify:deploy
```

Эта команда повторно собирает приложение с production-окружением и загружает страницы, API и фоновую функцию. Не добавляйте `--no-build`: важны выходные файлы адаптера Next.js. При успехе CLI напечатает адрес сайта. Обычная draft-публикация здесь не настроена: APP_ORIGIN и worker рассчитаны на один основной адрес.

После изменений кода повторяется deploy из той же папки. Git push сам по себе не обновляет сайт, поскольку интеграция GitHub не подключена. Изменения окружения Netlify также требуют нового deploy.

## 5. Проверить публикацию

1. При AI_ENABLED=false открыть сайт с двух устройств, рассчитать пример: Score `56,54`.
2. Сохранить сценарий, перезагрузить страницу и открыть его. После повторного деплоя сценарий должен сохраниться в Neon.
3. Включить AI и повторно опубликовать. Запустить один анализ, закрыть вкладку. Через несколько минут проверить статус и ответ в таблице analyses в Neon. Закрытие вкладки может удалить sessionStorage: автоматическое восстановление панели AI в новой вкладке этой версией не гарантируется. При простой перезагрузке той же вкладки сохранённый ID обычно остаётся.
4. Убедиться, что в Netlify видны Next.js server function и `analysis-background`. Проверить логи без вывода секретов.
5. Проверить отмену и повторную доставку одной задачи: уже завершённая задача не должна создавать новые AI-запросы.
6. Проверить запрос к внутреннему маршруту без WORKER_SECRET: HTTP 403. Проверить межсайтовую запись: HTTP 403.

До этих проверок нельзя считать облачную публикацию подтверждённой. Локальные тесты используют имитацию AI и PostgreSQL в PGlite; реальная доступность модели и связь с Neon требуют отдельной проверки.

## Выполнение и ограничения

POST /api/analyses создаёт запись и запускает исследование OpenAI, затем получает подтверждение приёма фоновой функции Netlify. Worker каждые четыре секунды вызывает защищённый внутренний API. API проверяет статус провайдера, запускает второй этап и сохраняет ответ. GET из браузера только читает состояние. Закрытие вкладки не останавливает worker; сознательная отмена или новый ход останавливают старую задачу.

Повторные доставки используют одну запись и блокировку этапа. Переход сохраняется до запуска второго платного этапа. Если процесс прервался между созданием ответа OpenAI и сохранением его ID, система помечает задачу как прерванную, а не автоматически оплачивает повтор. Это защита от дублей, не гарантия бесшовного восстановления любого сбоя.

Общий срок анализа — до 12 минут; цикл worker ограничен 14 минутами при лимите Netlify 15 минут. Отдельный вызов API остаётся коротким относительно полного анализа. При недоступности базы или платформы задача может завершиться ошибкой; бесплатный тариф не даёт гарантии бесперебойности. Долгое ожидание в worker, опросы, сборки и трафик расходуют кредиты Netlify; AI оплачивается отдельно.

Источники: [Next.js на Netlify](https://docs.netlify.com/build/frameworks/framework-setup-guides/nextjs/overview/), [Background Functions](https://docs.netlify.com/build/functions/background-functions/), [переменные функций](https://docs.netlify.com/build/functions/environment-variables/), [тарифы](https://www.netlify.com/pricing/).

## Подготовка и push в исходный репозиторий

Ветка изменений — `codex/netlify-latest`, база — `3700ece`. Это последняя подтверждённая локально версия origin/main, а не обещание отсутствия новых удалённых коммитов. Перед слиянием ветки нужно обновить сведения с сервера и проверить изменения команды. Исходная рабочая папка с чужими незакоммиченными правками не заменяется.

Из подготовленной рабочей копии проверьте staged diff, настройте своё имя и email автора (если ещё не заданы), создайте коммит и отправьте только эту ветку:

```powershell
git diff --cached --stat
git diff --cached --check
git commit -m "Prepare Netlify CLI deployment with Neon and background AI"
git push -u origin codex/netlify-latest
```

Настройка имени/email при необходимости: `git config user.name "ВАШЕ ИМЯ"` и `git config user.email "ВАШ EMAIL"`. Подставьте собственные данные, можно GitHub noreply. Не выполняйте force-push. Если push отклонён, сохраните текст ошибки и согласуйте изменения с командой.
