# Аким на 5 часов

**AI-симулятор городских решений: распределите бюджет, выберите пять инициатив и узнайте, как они изменят качество жизни районов Астаны.**

Городскому управленцу нужно одновременно развивать транспорт, озеленение, социальную инфраструктуру, безопасность и сервисы — при ограниченных ресурсах. Наш симулятор помогает управленцам, аналитикам и участникам игры сравнить последствия решений: кому станет лучше, какие проблемы останутся и чем придётся пожертвовать.

[Кейс и критерии хакатона](docs/case.md) · [Датасет](docs/data/dataset-source.md) · [Архитектура](docs/architecture/README.md) · [Развёртывание](docs/deployment.md)

## Что умеет

| Требование кейса | Реализация |
| --- | --- |
| Одинаковые стартовые условия | Бюджет **100**, пять районов, десять показателей, единый синтетический датасет |
| Пять управленческих решений | Каталог **14 инициатив** по всем пяти направлениям; выбор района для адресных мер |
| Контроль бюджета | Проверки стоимости, количества и совместимости мер в интерфейсе и повторно на сервере |
| Итоговый Astana Quality of Life Score | Воспроизводимый расчёт, графики «до/после», вклад мер и критические показатели |
| AI-анализ и объяснение компромиссов | Главный вывод, сильные стороны, риски, рекомендации, основания расчёта и источники |

Дополнительно: интерактивная карта, чат с советником, веб-поиск мировых практик, сохранение сценария вместе с итоговым AI-разбором и восстановление черновика.

Правило проекта: **ровно пять уникальных мер, максимум две на направление, расход ≤100**. Все направления доступны; брать по одной мере из каждого не обязательно.

## Как это работает

1. Пользователь выбирает инициативы и районы. Интерфейс сразу показывает расход и предварительные изменения.
2. Сервер проверяет выбор и заново вычисляет результат единым TypeScript-движком — стоимость и Score из браузера не принимаются на доверии.
3. По запросу пользователя AI исследует внешний контекст и объясняет серверный отчёт. Числовые основания выводятся из расчёта; мировой опыт не меняет коэффициенты модели.
4. Сценарий и готовое объяснение сохраняются для повторного просмотра без новой генерации.

Горизонт модели — **восемь кварталов**. Эффекты учитывают срок реализации, синергии и ограничения показателей:

```text
Эффект меры = полный эффект × (8 − срок реализации в кварталах) / 8
Score = 0.7 × средний индекс с учётом населения
      + 0.3 × индекс слабейшего района
      − число показателей ниже 40
```

Так итог учитывает и общий прогресс, и положение слабейшего района. Подробные правила — в [датасете](docs/data/dataset-source.md), реализация — [src/engine](src/engine/README.md). Движок отделён от AI: отказ модели не блокирует расчёт.

## Локальный запуск

Нужны **Node.js 22.20+** и npm; используемый менеджер — **npm 11.20.0**.

```bash
git clone https://github.com/BAITC-Hacks/hack-4078ad52-mama-papa-and-me.git
cd hack-4078ad52-mama-papa-and-me
npx --yes npm@11.20.0 ci
npm run dev
```

Откройте [127.0.0.1:3000](http://127.0.0.1:3000). Без ключа работают симуляция, отчёт и SQLite; вместо AI показывается явно обозначенное шаблонное объяснение. Для production-режима остановите dev-сервер и выполните `npm run build`, затем `npm start`.

**Чтобы включить настоящий AI:** создайте `.env` по [.env.example](.env.example), если файла ещё нет, заполните `OPENAI_API_KEY` и перезапустите сервер. Локально оставьте `DEPLOY_TARGET=local` и пустой `DATABASE_URL`. Нужны интернет и доступ к указанной модели. `AI_ENABLED=false` отключает платные вызовы.

Ключ хранится только на сервере. AI запускается по вопросу или кнопке разбора; подбор мер не расходует API-баланс. На настроенном облачном сайте посетителю собственный ключ не нужен — используется серверный ключ команды. Настройка Netlify, Neon, фонового обработчика и квоты описана [отдельно](docs/deployment.md).

## Проверка для жюри

1. Нажмите **«Загрузить пример» → «Рассчитать результат»**: расход **95**, Score **56,54**, прирост **3,99** относительно исходного **52,56**.
2. Нажмите **«Изменить решения»** и перенесите «Школа + детский сад» из Нуры в Есиль. После пересчёта Score станет **55,30**: место вложений влияет на результат.
3. При настроенном ключе нажмите **«Разобрать сценарий с AI»**. Проверьте вывод, риски и раскрываемые основания расчёта.
4. Сохраните сценарий и откройте его через **«Мои сценарии»**: итоговый разбор доступен без нового запроса.

Путь `/preview` — отдельное демо интерфейса с браузерным архивом и **без настоящего AI**. Для проверки серверной реализации используйте главную страницу.

## Тесты и воспроизводимость

```bash
npm test
npm run typecheck
npm run lint
npx playwright install chromium
npm run test:e2e
npm run build
npm run check:data
npm run check:docs
```

Последним двум командам нужен Python 3.9+. Vitest проверяет правила, серверные границы и жизненный цикл AI; SQL облачного адаптера тестируется через PGlite. Playwright проверяет основной пользовательский путь и демо. Автотесты подменяют AI и не расходуют API-баланс; E2E рассчитаны на локальный режим без облачных переменных окружения.

[Примеры реальных AI-ответов и найденные исправления](docs/reviews/ai-acceptance-2026-09-23.md) · [Журнал проверок и текущий статус](plans.md). Платные оценки запускаются отдельно: `node scripts/evaluate-ai.mjs --live`.

## Границы MVP и развитие

Это учебная модель на синтетических данных, а не официальный городской индекс или прогноз ВВП, зарплат и здоровья. AI может ошибаться; ссылки на факты не заменяют смысловую проверку. Облачный архив общий для посетителей, аккаунтов и приватных сценариев пока нет.

Следующие направления: сравнение команд, неожиданные городские события, экспорт презентации и калибровка на реальных данных. Сейчас реализованы расчёт, визуализация и объяснение сценария; эти дополнительные возможности не выдаются за готовые.

Устройство модулей — в [карте архитектуры](docs/architecture/README.md), условия публикации и ограничения доступа — в [руководстве деплоя](docs/deployment.md).
